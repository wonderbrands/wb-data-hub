Identificar devoluciones del mes en el reporte Amazon

Devolución registrada en Amazon
Cómo identificar devoluciones en el reporte BI 3.0
Col G — transaction_type = Refund
Col F — posted_date = mes bajo análisis
Dos tipos de movimiento dentro de Refund
description = Refund Devolución regular — el cliente devuelve el producto. Aplican los tres tipos de asiento (A / B / C).
description = DisbursementOnlyRefund Ajuste de fondos sin retorno de producto — equivalente a una bonificación. Solo aplica el asiento Tipo C.
Campos clave
Col C — order_id ID de la orden original en Amazon
Col D — so SO de Odoo ya cruzada en el reporte
Col Z — product_charges Monto devuelto (valor negativo). Base para la NC.
Col X — our_price_tax IVA devuelto (valor negativo). product_charges + our_price_tax = importe total de la NC.

Para que la NC quede debidamente vinculada y el proceso documentado
Nota para equipo de Data: Este paso es parcialmente redundante con el flujo de facturación — si el proceso de facturación corrió correctamente, toda orden de venta del mes ya debería tener SO y factura en Odoo antes de que se procese su devolución. La validación aquí actúa como salvaguarda. Queda a consideración de Data si implementarlo como un chequeo independiente o apoyarse en el resultado del flujo de facturación.

6

Aplicación del cobro en Odoo

Automático al registrar la NC en Odoo

Reverso de la aplicación de cobro
El comportamiento depende del estado de la factura de venta original al momento de registrar la NC:
Si la factura ya tenía cobro aplicado
La aplicación se rompe y se disminuye el saldo en Liberaciones Amazon Pendientes de Procesar.
Si la factura aún no tenía cobro aplicado
Se disminuye directamente la cuenta por cobrar 105-001-006 Amazon.
